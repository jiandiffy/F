工具接口以 `../../ui/desktop/PLUGIN_SPEC.md` 第10节为准。简单任务仍由主 Agent 执行，代码交付使用既有 delivered、simplify、test；自然语言交付加载并应用 unslop。

## 复杂任务

1. `goal_flow begin` 选择 complex，说明目标和允许修改的 paths。运行时先生成排除凭据的原始 Git 快照并上传私有 GitHub。失败时先修复发布，不能跳过基线开始实验。
2. 与用户讨论阶段目标树，再用 plan 提交 tree。根节点为总目标，children 依次为阶段，每个阶段可继续包含子目标。用户输入“批准阶段目标树”只批准一次。不要把当前任务的执行授权冒充用户对新目标树的批准。
3. propose 为每个入选起点启动3位方向作者，各写约200字的 summary 和具体 method、hypothesis、evaluation。主 Agent 阅读实际方法，判断是否成立、是否重复，再提交 review 的 judgments 和 distinctness。只让被否决者重提，不能先开实验再补审。
4. 全部方法通过后 run。每组三条分支都从该组固定起点提交创建独立工作树，实验者在自己的分支修改并用 project_version commit 提交。主 Agent 监督进度与失败，不代写实验结果。
5. 顶层实验者可自行 split 一次，1至3个孙实验者，孙不能继续拆分。子目标不再请用户批准。孙分支的精简和测试由主 Agent 派出独立代理，不能占用“最多3个实验孙代理”的名额。失败后 retry 恢复原实验者，不另造身份绕过失败记录。
6. 每条实验分支收口前依次经过精简和测试，两个代理身份不同，也不是该分支的实验者。测试必须真正执行，失败交回实验者修复，再用新的独立评审。所有分支成功后各自固定为候选并上传，主 Agent 应用 unslop，提交不超过1000字的阶段报告，比较方法、结果、证据和后续目标。
7. 用户输入“选择候选 1 3”等，挑选1至3个本阶段候选。下一阶段对每个入选版本再 propose 3位方向作者。只选择已测试并上传的固定版本，不用可移动的分支 HEAD 代替阶段起点，不重新请求目标树审批。

所有受管理的子代理，包括方向作者、实验者、孙实验者、精简者和测试者，只能使用 cbi / deepseek-v4.1-flash / medium，不能申请其他模型。
主线 skills 实时按需读取，datasets、已启用应用和 Cordis 工具沿用主线配置；显式工具白名单仍是权限上限。主线已审阅并启用的 HMR 插件按原哈希在子代理作用域挂载，不自动加载其他磁盘代码。

实验者先申请 resource_scope，重新读取后修改，完成后释放。主线保持只读，画板仍集中保存并通过矩形租约协调。磁盘、网络、认证与安装边界的必要错误处理必须保留。
取消保留工作树和已完成证据，不把部分完成标为候选。断网或额度耗尽后先核对已有提交、上传与工具结果，再 retry；结果不明的外部操作不能自动重放。
