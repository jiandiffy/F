# 一个目标如何在 F 中完成

主 Agent 负责一条会话的总线。总线上记录目标、阶段、启用的能力、资源申请和工具结果。插件先注册名称与说明，Agent 确认需要后才加载工具参数；技能正文也按需读取。

简单任务由主 Agent 完成。复杂任务先收集 arXiv、Zotero 和已有代码证据，再让三位不同领域的专家分别提出方案、阅读对方方案并投票。两票形成不超过 200 字的共识报告。你的意见会进入下一轮，批准后主 Agent 写不超过 1000 字的技术报告，修改确认后才执行。

审批记录属于实际用户输入，Agent 工具不能自行批准。状态机保存报告修订号，过期审批不能推进新方案。执行完成后，测试 Agent 根据目标列出子目标、测试方法和实际结果，测试报告不超过 1000 字。代码任务先交给简化 Agent，再由独立 Agent 做边界、随机和穷举测试。失败后主 Agent 选择重新规划或局部修复。自然语言交付调用 Cursor unslop。

一个文件夹拥有一张画板。Agent 先申请矩形和文件范围，再提交修改；不相交的区域可以并行，占用冲突会明确返回。每次画板修改检查新旧元素范围和场景版本，不能用旧场景覆盖别人的新图。旧会话画板合并后保留原档；队列、草稿和恢复记录仍按会话隔离。

GitHub 代码块保存仓库、提交和行号。Zotero 与 arXiv 论文保留来源和入库时间。论文的单位、性能和讨论度只有附上来源后才参与评分，缺少证据不视为低质量。以后接入其他数据库使用同一个 provider 接口。

版本插件用 Git 工作树表达任务树，每个子任务声明负责的文件。提交只包含该范围，合并前后都运行指定测试。GitHub 上传由项目菜单发起。文件插件在侧栏编辑文本、预览文档，复杂 Office 文档可交给默认应用编辑。
