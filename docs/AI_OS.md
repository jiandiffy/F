# F 的阶段实验流程

简单任务由主 Agent 完成。复杂任务先保存原始 Git 版本并上传私有 GitHub，然后由主 Agent 和用户讨论阶段目标树。用户只批准一次目标树，此后只在阶段结束时选择候选。

每个阶段起点派出3位方向作者，各写约200字简介。主 Agent 判断实验方法是否成立、是否重复；不通过者重提，通过前不创建实验工作树。方法全部通过后，从固定起点提交创建三条独立分支，实验者自行修改和 commit。

顶层实验者可自行拆分一次，最多3名实验孙代理，孙不能继续拆分。主 Agent 监督并为每条分支派出独立的精简者和测试者。两个评审不是同一个身份，也不是该分支的实验者。测试失败交回原实验者，修复后重新评审，不由用户介入。

每条分支收口为固定候选，上传后主 Agent 应用 unslop 写不超过1000字阶段报告。用户输入“选择候选 1 3”等挑选1至3个版本，下一阶段对每个入选版本再派3位方向作者。运行时记录真实用户输入和报告修订号，工具不能自行批准或选择。

所有受管理的子代理统一使用 cbi / deepseek-v4.1-flash / medium。主线 skills 按需读取最新正文，datasets 与已启用的应用工具共享；已批准的 HMR 工具按原哈希在子作用域挂载。显式工具白名单仍然生效。分支文件独立，主线只读，画板继续集中保存并由矩形租约协调。

GitHub 原始快照与候选快照按阶段父版本连接，不上传开发提交祖先。凭据路径排除、内容扫描和私有仓库检查都通过后才能上传。工作流采用独立远端分支，不改用户已有 origin 或强推。普通版本插件的手工发布入口保留。

取消和失败保留已完成提交与工作树。恢复时先核对已有工具结果，不能把部分完成记为候选。旧复杂工作流已退役，历史记录保留供查看；本机/SSH 项目、会话、队列、画板和普通版本功能继续保留。SSH 项目仍须具备远端 Git/工作树及租约提供方才能运行并行阶段实验，不会把本机 SSH 描述目录当作远端源码。
